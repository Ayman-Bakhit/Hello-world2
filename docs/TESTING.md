# Testing
- `pnpm test` runs vitest (shared package: fee split, tax engine, copy lint).
- DB: `db/schema.sql` must load on PG16 with `ON_ERROR_STOP=1`; to be automated in CI.
- Planned: API integration tests (auth replay/expiry), indexer idempotency, contract unit/invariant/fuzz tests, Playwright e2e for the seven flows in the spec.
- Web (`apps/web`): vitest covers formatting, fee-draft parsing (100.01% / 99.99% rejected via shared math), launch validation, mock-data consistency (totals, tax exposure recomputed with the shared engine), and a copy lint over all frontend source (banned phrases, positive safety claims).
- Browser checks used in Slice 3 (not yet automated in CI): every route loads, no horizontal overflow at 390px and 1440px, wallet modal, fee-split blocking, signing summary, Discover filters, table sort, zero console errors. Playwright e2e is planned.
- API (`apps/api`): 209 vitest tests run Fastify via `inject` against a **real PostgreSQL** database (`pn_api_test`, recreated each run from `db/schema.sql` + migrations + demo seed). Requires Postgres reachable at `TEST_ADMIN_DATABASE_URL` (default `postgresql://postgres:postgres@127.0.0.1:5432/postgres`). Covers: health, structured errors, Zod validation, fee-split rejection (API + DB), auth/authorization boundaries (every protected route 401 without a session; cross-user 404), portfolio, transactions, tax, tax-reserve target, charities, donations, launches + review, token proof, discover filters, CORS, rate limits, log redaction, config guards. Tests assert demo labeling. Slice 5 adds indexing tests that use a deterministic fake RPC (below); nothing here touches a real network.
- Shared (`packages/shared`): 90 tests including the chain parsing/classification/units tests (Slice 5) and the API contracts, builders, discover, launch review, and the sign-in message format/parser.
- Web: client tests cover mode switching, URL/header construction, error mapping, contract validation, and parity with shared fixtures.
- Wallet auth (`apps/api/test/wallet-auth.test.ts`, 47 tests, real Postgres, real Ed25519 keys from `@solana/keys`; ephemeral test keys only): nonce shape/uniqueness/expiry/cap/cleanup; valid sign-in (cookie flags, token never in body, DB rows); rejection of invalid/zero/other-key signatures, modified message, modified nonce, modified address, nonce for A used by B, signature from A used for B, replay, expired nonce, never-issued nonce, malformed signatures/messages/bodies; one-attempt-per-challenge; uniform failure bodies; repeated and concurrent sign-in without duplicate users/wallets; DB uniqueness and demo-wallet constraints; logout, expiry, rotation; CSRF/Origin rules; production cookie (`__Host-`, Secure) and rejection of dev sessions.
- Mutation check performed during Slice 2: breaking the address binding, single-use check, message comparison, or signature verification each turns the suite red.
- Web (132 tests): error mapping (`describeApiError`: 401/403/404/NO_LIVE_DATA/400/409/422/429/5xx/network, no leaks), client behavior for every endpoint in both modes (200/201/4xx/5xx, credentials, POST bodies), screen views rendered to static HTML (demo vs empty vs live labeling, AUTHENTICATION REQUIRED, empty portfolio/transactions/donations, tax language, reserve funds disabled, launch preparation, proof verification gating, discover filter mapping, authenticated wallet display), plus state-machine tests (CONNECTED never becomes AUTHENTICATED without a server session), Wallet Standard helper tests with fake wallets, auth client tests, and a source lint that no file uses localStorage/sessionStorage/document.cookie or mentions key material.
- Browser e2e, API mode (`apps/web/e2e/api-flow.e2e.mjs`, 60 checks, `pnpm --filter @project-name/web e2e:api`; `e2e:auth` is an alias): real API + migrated and seeded Postgres, web built with `NEXT_PUBLIC_API_MODE=api`, injected Wallet Standard "Phantom" that signs with a real Ed25519 key held by the test process. Flow: open, DISCONNECTED, connect (CONNECTED, still 401), wallet decline, sign, AUTHENTICATED, HttpOnly cookie, Portfolio / Tax / Tax Reserve empty states with no demo data attached, Give, Discover filters, Token proof, Launch (prepare, save, server review, list, detail, deploy unavailable), reload keeps session, replay rejected, logout (UI + server revoke), AUTHENTICATION REQUIRED afterwards.
- Browser smoke, mock mode (`apps/web/e2e/mock-smoke.e2e.mjs`, 82 checks, `E2E_WEB_URL=... pnpm --filter @project-name/web e2e:mock`): all routes at 1440px and 390px (no horizontal overflow, DEMO DATA labels), populated demo screens, wallet switching, reserve target validation and save, mock connection is never AUTHENTICATED, launch prepare/review, mobile navigation drawer, no console errors. Neither e2e script is in CI yet.

## Slice 5: Solana indexing tests
- **No test touches a real network.** `FakeSolanaRpc` (in-process) and `apps/api/scripts/fake-rpc-server.ts` (HTTP, for the browser run) are deterministic. Their transactions are RPC-shaped JSON that goes through the REAL parser, classifier and indexer.
- Shared (`chain/chain.test.ts`, 25): RPC parsing (valid, malformed, hostile), exact lamports above 2^53, classification rules and their negatives, Metaplex metadata parsing (padding, control/bidi stripping, URI allowlist, truncated/absurd lengths), unit/value math.
- API provider (`test/rpc-provider.test.ts`, 15): valid/malformed/timeout/HTTP-error/RPC-error responses, bounded retries, invalid addresses never reach the network, no URL or key in any error, Token + Token-2022 queries, signature mismatch, metadata owner check, price providers (exact decimal parsing, any failure means no price).
- API indexing (`test/indexing.test.ts`, 37, real Postgres): SOL and SPL balances, no fabricated symbols, empty wallet, zero-balance tokens hidden, untrusted metadata, decimals mismatch, vanished holdings, price rules (devnet none, mainnet priced/partial/stale), transaction classification and fee handling, raw immutability (UPDATE/DELETE rejected), pagination, shared transactions, **idempotent repeat sync (row counts unchanged, no refetch)**, incremental sync, initial limit, window-full gap flag, RPC call budget and restart, malformed and missing transactions, RPC failures (timeout, transient stop, internal error is generic), authorization (other user 404, 401, bad id, CSRF), cooldown 429 + Retry-After, per-IP rate limit, concurrent start, DB one-running-sync constraint, orphaned run sweep, indexing unconfigured (503, no demo substitution), no RPC URL in any response, cross-user isolation, login-triggered sync.
- Web (`screens.test.tsx` + `errors.test.ts`): live portfolio (LIVE DATA, PRICE DATA UNAVAILABLE never $0, mint identity, escaped untrusted metadata, partial sum labeled, empty wallet, no P&L), live transactions (FAILED, NOT ASSESSED, unknown date/price, explorer link allowlist), sync panel states (never synced, syncing, synced, failed, unconfigured, demo has no controls), cooldown/unconfigured error mapping.
- Browser, API mode (60 checks): with the fake RPC server, a real sign-in, then NO LIVE DATA, SYNC WALLET, LIVE DATA with 3.5 SOL and a token shown by mint with UNVERIFIED METADATA (hostile markup inert), PRICE DATA UNAVAILABLE, 3 transactions (FAILED, NOT ASSESSED, explorer link), repeat sync refetches nothing and creates no duplicates, a new transaction appears after REFRESH DATA (exactly one fetch), cooldown 429, API never exposes the RPC URL. Run order for local: see ENVIRONMENT.md. The e2e API process needs `RATE_LIMIT_MAX`/`RATE_LIMIT_WRITE_MAX`/`INDEXER_SYNC_RATE_LIMIT_MAX` raised (back-to-back runs otherwise hit the limiter, which is working as designed).
- **Manual real-RPC smoke test** (`pnpm --filter @project-name/api smoke:rpc`, needs `SOLANA_RPC_URL` and `SMOKE_WALLET_ADDRESS`): read-only calls against a real node for a public address. Not part of `pnpm test`, not run in CI, and **not run in the build sandbox** (its network policy blocks RPC and price hosts). Until someone runs it, real-network behavior (response shapes at scale, Metaplex PDA derivation, rate limits of your provider) is unverified.
